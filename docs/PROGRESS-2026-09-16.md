## 一、本轮完成的核心验证闭环

### 1. 关键 Bug 修复（真机运行发现）
在 Xvfb 下真实运行应用截图，发现状态栏恒显示「⚠ FFmpeg 未就绪」。
根因：Rust 侧 `#[serde(rename_all="camelCase")]` 序列化输出 `ffmpegOk`，而前端读 `ffmpeg_ok` → undefined → 恒判定未就绪。

**全前端字段系统性对齐**（约 46 处）：
| 类型 | 修复 |
|---|---|
| EngineInfo | `ffmpeg_ok→ffmpegOk`、`ffmpeg_version→ffmpegVersion` |
| AppSettings | `output_dir→outputDir`、`rename_template→renameTemplate`、`watch_dir→watchDir`、`watch_preset→watchPreset` |
| QueueItem/JobState | `input_path→inputPath`、`preset_id→presetId`、`input_size→inputSize`、`output_size→outputSize`、`output_path→outputPath` |
| ProgressEvent | `job_id→jobId` |
| CompressItem/WatchRequest/EditOptions | `inputPath/outputDir/presetId`、`trimStart/trimDuration/cropPercent` |
| checkUpdate | `updateUrl` |

Rust 侧逐一核实：EngineInfo/AppSettings/JobState/ProgressEvent/CompressItem/EditOptions 全部已带 `rename_all="camelCase"`，**前后端完全对齐**。
